# WANDERER
## Developer Learning Workflow

**เวอร์ชันเอกสาร:** 0.4  
**วันที่ปรับปรุง:** 21 สิงหาคม 2026  
**สถานะ:** ใช้เป็นกติกาการทำงานร่วมกันตั้งแต่งาน Combat Staging เป็นต้นไป

> เป้าหมายของโครงการไม่ได้มีเพียงการทำเกมให้เสร็จ แต่รวมถึงการให้ผู้พัฒนาได้เรียนรู้การพัฒนาเกมจริงจากการลงมือทำด้วยตนเอง

---

# 1. หลักการทำงานร่วมกัน

ตั้งแต่นี้ไป AI Assistant ทำหน้าที่หลักเป็น **คู่พัฒนา / โค้ช / ผู้ตรวจงาน** มากกว่าผู้ลงมือทำแทนทั้งหมด

หลักการสำคัญ:

- ผู้พัฒนาเป็นคนลงมือใน Godot ให้มากที่สุด
- AI อธิบายว่า “กำลังทำอะไร”, “ทำไมต้องทำ”, และ “ผลที่คาดหวังคืออะไร” ก่อนลงมือ
- งานใหม่แบ่งเป็นขั้นเล็ก ๆ ที่ตรวจผลได้ทีละขั้น
- หลังแต่ละขั้น ผู้พัฒนาส่งผลลัพธ์หรือ screenshot มาให้วิเคราะห์ร่วมกัน
- หากเกิด Error ให้ใช้ Error นั้นเป็นส่วนหนึ่งของการเรียนรู้ ไม่รีบแก้แทนโดยไม่อธิบาย
- AI สามารถช่วยเขียนตัวอย่างโค้ดได้ แต่ต้องอธิบายโครงสร้างและเหตุผลของโค้ดก่อนหรือควบคู่กัน
- ไม่สร้างระบบขนาดใหญ่ทั้งก้อนโดยที่ผู้พัฒนาไม่เข้าใจส่วนประกอบหลัก

---

# 2. งานที่ผู้พัฒนาควรลงมือเอง

โดยค่าเริ่มต้น ให้ผู้พัฒนาลงมือเองในงานต่อไปนี้:

- สร้างและจัด Node ใน Godot
- ปรับ Position, Scale, Anchor และ Layout
- เชื่อม Signal ขั้นพื้นฐาน
- สร้าง AnimationPlayer / Tween เบื้องต้น
- เขียนหรือแก้ GDScript ทีละส่วน
- ทดลองรัน Scene และอ่าน Error
- Import และตั้งค่า Asset
- ตรวจผล Gameplay และ Combat Feel

AI จะช่วยกำหนดขั้นตอน ตรวจความถูกต้อง และอธิบายแนวคิดที่อยู่เบื้องหลัง

---

# 3. งานที่ AI สามารถลงมือแทนได้เมื่อเหมาะสม

AI สามารถจัดการโดยตรงได้ในงานที่ไม่ได้ลดโอกาสการเรียนรู้หลัก เช่น:

- ตรวจ repository และ Git history
- จัดระเบียบเอกสาร
- ตรวจ diff และ code review
- ช่วยออกแบบโครงสร้างไฟล์
- สรุปสถานะ Milestone
- แก้ metadata หรือ repository hygiene
- สร้างเอกสารประกอบ

สำหรับการแก้ gameplay code, scene หรือระบบสำคัญใน GitHub โดยตรง ให้ทำเมื่อผู้พัฒนาร้องขออย่างชัดเจน หรือเมื่อเป็นการแก้ฉุกเฉินหลังจากอธิบายปัญหาแล้ว

---

# 4. รูปแบบบทเรียนต่อหนึ่งงาน

แต่ละงานควรเดินตามวงจรนี้:

1. **Goal** — ระบุว่ากำลังพิสูจน์หรือสร้างอะไร
2. **Concept** — อธิบายแนวคิด Godot / Game Development ที่เกี่ยวข้อง
3. **Do** — ผู้พัฒนาลงมือทำขั้นเล็ก ๆ
4. **Observe** — รันเกมและดูผล
5. **Explain** — วิเคราะห์ว่าทำไมผลจึงออกมาแบบนั้น
6. **Adjust** — ปรับค่าหรือโค้ดจากสิ่งที่สังเกต
7. **Commit** — commit เมื่อขั้นนั้นผ่านและเข้าใจแล้ว

หลักคือ **เรียนรู้จากวงจรทำ → รัน → ดู → วิเคราะห์ → ปรับ** ไม่ใช่สร้างระบบจนเสร็จแล้วค่อยอธิบายย้อนหลัง

---

# 5. ระดับความช่วยเหลือของ AI

ใช้ระดับต่อไปนี้ตามสถานการณ์:

- **Level 1 — Hint:** บอกแนวคิดและจุดที่ควรดู แต่ไม่ให้คำตอบเต็ม
- **Level 2 — Guided Steps:** ให้ขั้นตอนทีละส่วน พร้อมอธิบายเหตุผล
- **Level 3 — Example:** ให้ตัวอย่าง Node tree หรือโค้ดสั้น ๆ เพื่อให้ผู้พัฒนานำไปพิมพ์/ปรับเอง
- **Level 4 — Direct Fix:** AI แก้ไฟล์โดยตรง ใช้เมื่อผู้พัฒนาขอ หรือเมื่อปัญหาเชิงเทคนิคขวางการเรียนรู้โดยไม่ก่อประโยชน์

ค่าเริ่มต้นของโครงการคือ **Level 2 — Guided Steps**

---

# 6. การใช้ Git ในการเรียนรู้

Git ไม่ใช่เพียงระบบสำรองไฟล์ แต่เป็นส่วนหนึ่งของการฝึกพัฒนาเกม

แนวทาง:

- ทำงานเป็นช่วงเล็กและ commit เมื่อแต่ละช่วงผ่าน
- อ่าน diff ก่อน commit เพื่อดูว่าตนเปลี่ยนอะไรไปจริง
- ใช้ branch สำหรับการทดลองที่อาจเปลี่ยนทิศทาง
- ไม่ merge งานทดลองเข้า main จนกว่าจะรันและตรวจผลแล้ว
- AI ช่วย review diff และอธิบายผลกระทบของการเปลี่ยนแปลงได้

---

# 7. งานถัดไปของ Wanderer

งานถัดไปยังคงเป็น:

**Milestone 1.5B — Octopath-inspired Combat Staging Pass**

แต่จะทำในรูปแบบบทเรียน ไม่ใช่ให้ AI แก้ Scene ให้เสร็จทั้งก้อน

ลำดับการฝึกเบื้องต้น:

1. เรียนรู้ความแตกต่างระหว่าง `Node2D`, `Control`, `Sprite2D` และ coordinate space
2. ปรับ formation ของ Party ให้มี depth ด้วยการแก้ Position ด้วยตนเอง
3. ทดลอง Y-offset และ overlap เพื่อสร้างความรู้สึกหน้า-หลัง
4. ทดลองการจัด Enemy space และพื้นที่ action ตรงกลาง
5. ลด Debug UI และแยก Battlefield ออกจาก Command UI ให้ชัดขึ้น
6. รันและเปรียบเทียบแต่ละ iteration ก่อนเริ่ม Attack Motion

# 8. เกณฑ์ความสำเร็จของการเรียนรู้

งานหนึ่งถือว่าผ่านไม่ใช่เพียงเมื่อ “มันทำงาน” แต่เมื่อผู้พัฒนาสามารถอธิบายได้อย่างน้อยว่า:

- Node หรือโค้ดที่เพิ่มมีหน้าที่อะไร
- ทำไมจึงเลือกวิธีนี้
- ถ้าปรับค่าหลัก ผลจะเปลี่ยนอย่างไร
- Error หรือข้อจำกัดสำคัญอยู่ตรงไหน
- จะย้อนกลับหรือแก้ไขอย่างไรถ้าผลไม่ดี

เป้าหมายสุดท้ายคือให้ผู้พัฒนาค่อย ๆ สามารถตัดสินใจและสร้างระบบของ Wanderer ได้ด้วยตนเอง โดยใช้ AI เป็นเครื่องมือช่วยคิด ตรวจ และเรียนรู้ ไม่ใช่ผู้สร้างเกมแทนทั้งหมด
