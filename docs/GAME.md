# WANDERER — Game Design (เอกสารหลัก)

**สถานะ:** แผนเกมปัจจุบัน • รวบรวมจาก v0.1–v0.5 เมื่อ 10 ต.ค. 2026  
**ขอบเขต:** กติกาและเป้าหมายเกม **ไม่ใช่รายงานว่าระบบทั้งหมดเขียนแล้ว**  
**อ่านคู่:** [WORLD.md](WORLD.md) (โลก/เรื่องเล่า) และ [WORKFLOW.md](WORKFLOW.md) (Milestone/วิธีลงมือ)

## 1. ตัวตนของเกม [LOCKED]

- **2D Pixel Art, side-view, party-based RPG**; เดินทาง รับเควส วางแผน ต่อสู้แบบ tactical/turn-based ที่ยังทดสอบรูปแบบรอบ
- **ผู้เล่นคุมตัวละครของตัวเองเพียงหนึ่งคน** ร่วมทีมกับ **NPC สูงสุด 3 คน**; NPC มีเป้าหมาย บุคลิก อิสระในการทำ/ไม่ทำตามคำชี้นำ
- **Permadeath** เป็นผลลัพธ์จริง แต่โลกและความก้าวหน้าระดับเซฟดำเนินต่อได้เมื่อผู้เล่นสร้าง/เลือกตัวละครใหม่
- ตัวละคร **ไม่ได้เลือก Class ตั้งแต่สร้าง**; ความชำนาญ/บทบาทเติบโตจากการกระทำในสถานการณ์ที่มีความหมาย
- โทนภาพสดใส อ่านง่าย แต่ความสูญเสียและการตัดสินใจมีน้ำหนัก; ผู้เล่นผูกพัน NPC ผ่านพฤติกรรม ไม่ใช่แค่คะแนนสัมพันธ์
- **Single-player, Premium, Offline**, ไม่มี gacha หรือขายพลัง/การชุบชีวิต

## 2. Loop และหน้าหลัก [LOCKED]

เมือง (Town UI) → เลือก/รับ Quest → ชักชวน NPC/จัดอุปกรณ์/เสบียง → เลือกเส้นทางบน **Node Route Map** → Journey Event → ต่อสู้/เจรจา/หลีกเลี่ยง/ถอย → กลับเมืองหรือถึงจุดหมาย → ผลลัพธ์ ชื่อเสียง บาดแผล รางวัล และเปิดเส้นทาง

มีหน้าหลักสามประเภท: **Town UI**, **Journey Node Map**, **Side-view Combat**. ไม่ทำ walkable open-world town ใน Vertical Slice. ศูนย์นักผจญภัยจัดการเควส การรับสมัคร ข่าว ใบอนุญาต แผนที่และบันทึกความคืบหน้าระดับเซฟ

**Quest archetypes:** คุ้มกัน ขนส่ง สำรวจ ติดตาม กำจัดภัย; การแก้โดยไม่ฆ่าก็สำเร็จได้. เส้นเรื่องระดับโลกเกี่ยวข้องกับ **การเปิดเส้นทางโบราณที่เชื่อมโลกใหม่** แต่ไม่ได้บังคับเฉลยโลกเก่าตั้งแต่ต้น

## 3. Combat baseline [LOCKED/OPEN แยกกัน]

- Side-view และ party 1+3 **[LOCKED]**; **Turn System [OPEN]**: Classic Turn-based, Intent Round, ATB หรือแบบอื่นหลังทดสอบ pacing ของ NPC
- สำหรับ functional prototype ทดลอง classic turn-based: Player/NPC/Enemy เลือก intent, ใช้ Speed จัดลำดับ, resolve ทีละ action **[PROTOTYPE ไม่ใช่ final combat contract]**
- Action ขั้นต่ำ: **Attack, Defend, Help, Retreat**; คำชี้นำ NPC: โจมตี ตั้งรับ ช่วยคนเจ็บ รักษาระยะ เตรียมถอย หนีทันที
- สนามเริ่มจาก Front/Back **[PROTOTYPE]**; การแสดงความลึกแบบ diorama ไม่เท่ากับเปลี่ยนเกมเป็น tactical grid
- NPC ตัดสินใจจากลักษณะนิสัย เป้าหมาย ความไว้ใจ ความบาดเจ็บ ความเสี่ยง ข้อมูลที่รู้ ทักษะ และคำชี้นำ; ให้เหตุผลอ่านออกเมื่อ NPC ปฏิเสธ/ลังเล/ช่วยคนอื่น
- คำชี้นำไม่ใช่ปุ่มสั่ง NPC ที่บังคับสำเร็จ และ NPC ไม่จำเป็นต้องตัดสินใจถูกเสมอ

### Combat presentation [CURRENT DESIGN]

ใช้แรงบันดาลใจ **Octopath-inspired staging** เท่านั้น ไม่ลอก asset/composition. ฉากต้องไม่เป็นคนเรียงแบน 4 ตัว; เยื้องหน้า-หลังโดยยังอ่านออกชัด; Player เป็นจุดสังเกต, Enemy อยู่ในพื้นที่ของ battlefield, กลางจอมี Action Space, debug UI ไม่แย่งพื้นที่. ทดสอบ **1280×720**, integer sprite scale ×4 ในต้นแบบ [PROTOTYPE]; camera/2.5D/turn layout ยัง [OPEN]. ใช้ Tween/AnimationPlayer, emphasis, lunge, hit flash, recoil, damage text, return position ก่อนต้องวาด attack sprites จำนวนมาก. เอฟเฟกต์ต้องสั้น ไม่บดบังการตัดสินใจของ NPC.

## 4. Actor model, progression [บางค่าเป็น PROTOTYPE]

**คุณลักษณะฐาน 6 ค่า** ช่วงทดสอบ 1–10 ค่าเฉลี่ยประมาณ 5:
พละกำลัง, ความคล่องตัว, ความทรหด, การรับรู้, จิตมั่นคง, อิทธิพล. ค่าที่คำนวณต่อได้: HP, Damage, Accuracy, Evasion, Armor, Speed และ Guidance Power. ต้นแบบยังไม่ต้องใช้สถานะทุกชนิด

**ค่านิสัย NPC 5 แนว**: ความกล้า, วินัย, เมตตา, สัญชาตญาณเอาตัวรอด, ความทะเยอทะยาน **[PROTOTYPE]**; **Trust [LOCKED] เป็นความสัมพันธ์ระหว่าง NPC กับ Player character เฉพาะคน** ไม่สืบทอดให้ตัวละครใหม่โดยอัตโนมัติ. การแบ่งอาหาร ช่วยชีวิต รักษาคำสัญญา การทอดทิ้ง มีผลต่อ Trust

**Skills [LOCKED]** เติบโตจากการใช้จริงในสถานการณ์เสี่ยง ไม่ให้ grind ง่าย; ช่วง 0–5 เป็นแนวเกณฑ์: ไม่เคยฝึก → คุ้นเคย → ฝึกฝน → ชำนาญ → เชี่ยวชาญ → ยอดฝีมือ. ตัวอย่าง ดาบ หอก โล่ ธนู แพทย์ สำรวจ เอาตัวรอด/โบราณวัตถุ

**Level [PROTOTYPE]** อาจ 1–20 เติบโตไม่ทวีคูณ; XP ไม่ขึ้นจากฆ่าศัตรูเป็นหลัก แต่ได้จากเควส สำรวจ เอาตัวรอด ช่วยเหลือ ใช้ทักษะ และการเดินทาง. **Class [LOCKED concept]** เป็นชื่อบทบาท/ความสามารถที่ผู้คนยอมรับจากสิ่งที่ตัวละครทำ (นักรบ ผู้พิทักษ์ นักล่า ผู้รักษา ฯลฯ) ไม่ล็อกอาวุธหรือ skill tree ตั้งแต่สร้าง

**Player creation:** เลือกชื่อ รูปลักษณ์ เพศ ภูมิหลัง แรงจูงใจ ค่านิยม; คำถามเริ่ม 3 ข้อเป็น [PROTOTYPE] และไม่กำหนด Class. ผู้เล่นอาจมีหลายตัวละคร แต่ควบคุมทีละหนึ่งคน

## 5. Injury, death & persistence [LOCKED concept]

- เมื่อ HP = 0 เข้าสถานะ **Down** ก่อนตาย: อาจเลือดออก โดนซ้ำได้ เพื่อนช่วย/ลาก/แบกได้ในเวลาจำกัด
- ทุกคนตายถาวรได้; **Player ตายไม่เท่ากับ Game Over**. NPC ที่ยังอยู่ตัดสินใจต่อว่าจะสู้ หนี ช่วยหรือเก็บศพตามสภาพและความสัมพันธ์
- การกู้ศพอาจสำเร็จ สูญหาย หรือไม่มีผู้รอด; น้ำหนัก ระยะทาง สถานการณ์และความรู้สึกมีผล
- ความก้าวหน้าระดับตัวละคร (Level/Skills/Class/Trust ส่วนตัว/อุปกรณ์ที่พก) เสี่ยงสูญเสียเมื่อเสียชีวิต; **ความก้าวหน้าระดับเซฟ/ศูนย์ฯ** เช่น เส้นทาง ข่าว แผนที่ ข้อมูลศัตรู บันทึกผู้ตาย และของฝากยังคงอยู่ตามกฎเกม
- **ความเป็นไปได้ของการคืนชีพ** เป็นความลับที่มีเบาะแส แต่ไม่ใช่ไอเทมชุบฟรีหรือปุ่มใน combat; กลไก ราคาที่ต้องจ่าย และการกลับคืนอยู่ใน [LATER/OPEN] ห้าม implement ใน prototype แรก

## 6. Journey design [PROTOTYPE]

หนึ่งเส้นทางเริ่มด้วย **ระยะทาง ภูมิประเทศ อันตรายโดยประมาณ และสิ่งอาจพบ**; ข่าว/แผนที่อาจคลาดเคลื่อนอย่างมีเหตุผล ไม่ซ่อนทุกอย่างจนเลือกไม่ได้. ตัวเลือกที่ทดลอง: ความเร็ว (ระวัง/ปกติ/เร่ง), แนวทางของทีม (หลีกภัย/หาเสบียง/มุ่งตรง), NPC อาจเห็นต่าง. Event จากสถานที่ สมาชิกทีม หรือโลก/การเดินทางเก่า; อาการบาดเจ็บและความต้องการถอยต้องมีผลจริง

## 7. Starstone / Resonance — แนวคิดเกมอนาคต

**กฎโลกที่ต้องรักษา [LOCKED INTENT]:** พลังพิเศษมีจริง คนทั่วไปทราบว่ามีแต่พบเห็นจริงยาก; ต้องอาศัยวัสดุจากอุกกาบาตที่ผ่านการฝัง/ขึ้นรูปเป็นอาวุธ เครื่องมือ หรือเครื่องประดับ; ไม่ร่ายมือเปล่าทั่วไป, ไม่มีสกิลเวทฟรีซึ่งแทนการช่วย/โจมตีธรรมดาทุกสถานการณ์

**รายละเอียดเชิงกลไก [DESIGN BASELINE/PROPOSED]:** ใช้การพ้องพลัง (Resonance) พร้อมค่าเหนื่อย **User Strain**, และความเสื่อม/ความเครียดของแกนวัสดุ **Material Stress/Integrity**. ต้องมีสัญญาณเตือนก่อนความเสี่ยงหนัก; NPC ตัดสินใจใช้/ไม่ใช้โดยอิสระ; ไม่ชุบ Dead ด้วยอุปกรณ์รักษาทั่วไป. ต้นกำเนิดหายนะและความเกี่ยวข้องของอุกกาบาตยัง [OPEN]

**เมื่อพร้อมทดลอง [OPTIONAL M4.R; ห้ามแทรก M1.5B]:** MRE-1 อุปกรณ์ตัวอย่าง **Pulse Pendant** ช่วยชะลอ bleed-out/ประคอง Alive หรือ Down เพียงครั้งเดียวต่อ encounter ในต้นแบบ แล้วเข้าสู่ Spent; ไม่คืนชีพ; ไม่มีระบบคราฟต์เหมือง ตลาดผลึกหรือ rarity economy. ทดสอบ no-item, equipped, spent, invalid/dead target, NPC เลือกใช้/ไม่ใช้, guidance conflict, reset/end combat. ถ้ารบกวน Core Loop ให้เลื่อนออกไปหลัง M7 ได้

## 8. Scope rules

- **Prototype ปัจจุบัน ≠ เกมเสร็จแล้ว**; เอกสาร lore ไม่ยืนยันว่ามีระบบนั้นในโค้ด
- ไม่ทำ RPG open world, real-time economy, multiplayer, full crafting/mining, procedural world, skill VFX จำนวนมาก หรือแอนิเมชัน/Asset ขั้น final ก่อนพิสูจน์ core
- แยก [LOCKED], [PROTOTYPE], [OPEN], [LATER], [CUT]. เมื่อเปลี่ยนการตัดสินใจหลัก ให้แก้เอกสารนี้และบันทึกเหตุผล ไม่ออกเอกสาร version ต่อท้ายใหม่เรื่อย ๆ
