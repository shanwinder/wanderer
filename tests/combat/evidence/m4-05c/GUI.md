# GUI, keyboard and presentation record

14 November 2026 (Asia/Bangkok). Agent-operated macOS Godot windows on Apple M1 / arm64, macOS 27.0.1 (26A434), OpenGL 4.1 Metal 91.7 / Compatibility. Godot `4.7.2.stable.official.ed1daf0bf`, executable SHA-256 `c7cccbf8fb143e34e02fd6521e09be2c2b974f0d5db080b19071c9c570718ccf`. All three entries use source `fd1d00d7a63603d637f900730927a6a59e01f675`.

Use the commands below from the pinned repository root. The default command resolves the same configured entry as editor F5. The two explicit scene commands resolve the same entries as opening the corresponding scene and using editor F6. These runs used standalone Godot windows.

```sh
GODOT_BIN=/Applications/Godot.app/Contents/MacOS/Godot
EVIDENCE=tests/combat/evidence/m4-05c
mkdir -p "$EVIDENCE/logs"
"$GODOT_BIN" --headless --path . --import --log-file "$EVIDENCE/logs/import.log" > "$EVIDENCE/logs/import-console.log" 2>&1
"$GODOT_BIN" --path . --resolution 1280x720 --position 40,60 --log-file "$EVIDENCE/logs/main.log"
"$GODOT_BIN" --path . --resolution 1280x720 --position 40,60 --log-file "$EVIDENCE/logs/legacy.log" --scene res://scenes/combat/combat_prototype.tscn
"$GODOT_BIN" --path . --resolution 1280x720 --position 40,60 --log-file "$EVIDENCE/logs/b5.log" --scene res://scenes/combat/combat_m4_playable_optin.tscn
```

Repeat the B5 command with `b5-retry.log` or `b5-guided.log` for a fresh session. [Unaltered engine and console logs](engine-logs.zip) and exits are indexed in [run record](run.json). All captures are unmodified Computer Use JPEGs of the actual Godot window, 1280×784 including 64 px of macOS title chrome above the 1280×720 game content. [Capture provenance](captures.json) includes response timestamps, call IDs and SHA-256. Inputs were native key events and clicks through Computer Use. The macOS AX tree exposes window chrome only. Godot focus is visible in the rendered UI. Some window calls failed or needed a fresh AX snapshot after window changes. The first B5 session temporarily stopped responding to inputs after a Restart; a fresh launch restored control, and subsequent in-game resets retained keyboard control. Treat that specific window failure as unclassified input delivery, outside the two reproduced findings.

## Visual timing

All three starts show the same compact homes. The six root positions and 0.70 motion speed / 44 px lunge are confirmed in source. Sampled attack frames show short forward motion and reaction tint at the same time as reduced HP; later frames show the actors back at home. Main and Legacy also show a floating −5. B5 places the numeric change in the log and HP card and identifies the actor/target in the intent line. Adjacent allied poses overlap briefly in Legacy (NPC 3 and Player); actor cues remain legible in the sampled frame. B5 death, retreat, Guard and HP changes remain readable in retained cards. A fast-moving log can scroll reasons out of view, making keyboard return from it especially important.

B5 [terminal impact frame](screens/b5-victory-impact.jpg) shows Enemy B 0 and VICTORY before any completion line for the final attack. [Next sampled frame](screens/b5-victory-complete.jpg) adds completion #24 at the same HP. [Enemy B intent](screens/b5-enemy-b-intent.jpg) during the Defend run shows Player still at 29 before the second hit; [final close](screens/b5-exhaustion.jpg) shows 28, its completion, then round closure. These are sampled event order and visible effects. Exact pixel travel, sub-frame onset, comparative windup/return durations and absence of transient effects between samples remain unmeasured. No video or frame-calibrated timings were recorded. [Owner questions](OWNER.md) cover the pace and whether players can explain reasons from what they see.
